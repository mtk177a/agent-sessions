# ChatGPT Data Export プロバイダー

> **注記:** [英語版](../chatgpt.md) が正式版である。
> この日本語版は参考訳である。
> 内容に差異がある場合は英語版を優先する。

この文書では、`chatgpt` アダプターで保存済みの ChatGPT Data Export ZIP を読み取る方法と、出力の読み方を説明する。\
共通の `v2` JSON フィールドは [CLI 仕様](cli-json-contract.md) を参照する。

## 利用手順

### 1. エクスポート ZIP を用意する

アダプターを使う前に、エクスポートを申請してダウンロードする。\
ChatGPT の設定または Privacy Portal での申請方法は、OpenAI の [エクスポートの案内](https://help.openai.com/en/articles/7260999-how-do-i-export-my-data) に従い、案内された有効期間内にダウンロードする。\
`agent-sessions` は、エクスポートの申請、完了の定期確認、自動検出、ダウンロードを行わない。

<a id="エクスポート-zip-を選ぶ"></a>
<a id="エクスポート-zip-の指定"></a>

### 2. エクスポート ZIP を指定する

各アーカイブは、名前付きソースインスタンスとして指定する。\
ルートには、ディレクトリではなく、読み取る ZIP ファイルそのものを指定する。\
このプロバイダーには、ルートを指定する環境変数も既定のルートもない。

次のいずれかの方法で ZIP を指定し、会話の一覧を取得する。

#### コマンドで指定する

`--provider chatgpt`、`--source-instance`、`--root` を使う。

```sh
agent-sessions list --provider chatgpt --source-instance chatgpt-export --root /fictional/chatgpt-export.zip
```

#### 設定ファイルで指定する

[設定ファイル](cli-json-contract.md#設定) に明示的な項目を追加する。\
たとえば、次のように指定する。

```json
{
  "schema_version": "v1",
  "sources": [
    {
      "id": "chatgpt-personal",
      "provider": "chatgpt",
      "root": "/fictional/chatgpt-export.zip"
    }
  ]
}
```

その後、設定済みのインスタンスにある会話を一覧にする。

```sh
agent-sessions list --provider chatgpt --source-instance chatgpt-personal
```

### 3. 会話を読み取る

`list` の結果から、読み取る会話の `identity.source_ref` を次のプレースホルダーにコピーする。\
コマンドで ZIP を指定した場合は、この操作と後続のソース操作にも同じ `--root` を渡す。

```sh
agent-sessions events --root /fictional/chatgpt-export.zip '<source_ref from list>'
```

設定済みのインスタンスを使う場合は、設定ファイルから保存場所を取得できるため、このコマンドの `--root` を省略する。

## 出力の読み方

### 取得したデータ

`data` フィールドには、操作で要求した情報が入る。\
以下の節では、返却するデータの種類ごとに内容を説明する。

<a id="操作ごとの対応範囲"></a>

#### ソース情報

`list` と `show` は、会話の情報を返す。\
選択中の分岐から最後のやり取りの時刻を確定できる場合は、`last_interaction_at` を含む。\
確定できない場合はフィールドを省略し、`source_time_unavailable` を付けて `partial` を返す。

<a id="読み取る会話の分岐"></a>
<a id="返却する内容と取り扱い"></a>

#### イベント

`events` は、会話で現在選択されている分岐から、対応する観測を返す。\
ほかの分岐は省略し、`non_active_branch` を報告する。\
分岐を読み取れない場合は不完全な結果として報告し、順序を作り出したり、報告せずに分岐を短縮したりしない。

メッセージとツール結果には、共通の本文の上限を適用する。\
読める文字列は保持し、非テキスト部分や未対応の部分を除外したことは報告する。

##### メッセージ

ユーザーとアシスタントのメッセージから、テキストとマルチモーダルテキストの文字列部分を返す。

##### ツール結果

ツールロールの読める結果も返す。\
呼び出しとの対応と成否は確定できず、省略として報告する。

#### 検証済みバージョン

`verify` は、ZIP 全体を対象とする検証済み内容のバージョンを返す。

<a id="不完全な結果と失敗の扱い"></a>

### 処理の状態

状態を示すフィールドを使って、完全な観測、不完全な観測、未対応の入力、処理の失敗を区別する。

#### 状態を示す status

返却する状態の意味は、次のとおりである。

| 状態 | 意味 |
| --- | --- |
| `complete` | 観測した内容を完全に表現できた。 |
| `partial` | 有用な情報は得られたが、一部を省略している。 |
| `unsupported` | 入力は認識できたが、安全に使える有用な観測を返せない。 |
| `error` | 処理に失敗した。原因は `error` で確認する。 |

未知の内容やノードがあっても、有用なイベントが残る場合は `partial` を返す。\
省略後に安全に使えるイベントが一つも残らない場合は、`unsupported` を返す。\
認識できるが互換性のない JSON 構造も、不正な入力として扱わず、`unsupported` を返す。

<a id="やり取りの時刻"></a>

#### 省略理由を示す omissions

プロバイダー固有の省略は、次のコードで説明する。

| コード | 条件 |
| --- | --- |
| `non_active_branch` | 選択中の分岐にないノードを省略する。 |
| `unknown_node` | 選択中のノードや、その内容が未知である。 |
| `unsupported_format` | アーカイブの JSON 構造や会話グラフが未対応である。選択中のノードの欠落や親リンクの循環を含み、対象の操作は `unsupported` を返す。 |
| `source_time_unavailable` | `list` または `show` で最後のやり取りの時刻を確定できない。`last_interaction_at` を省略し、`partial` を返す。 |
| `event_time_omitted` | 元のメッセージの `create_time` が欠落しているか、不正である。`events` は `partial` を返す。 |

ツール結果では、呼び出しとの対応関係と成否が不明であることも省略として報告する。

#### 失敗の原因を示す error

不正な ZIP データ、不正な JSON、重複メンバー、安全でないメンバー、ソースの置換、リソース制限に関する失敗には、それぞれ異なる構造化エラーコードを付ける。\
エラーのフィールドとコードは、共通の [エラー仕様](cli-json-contract.md#エラーと終了コード) を参照する。

<a id="アーカイブの上限"></a>

## 入力の上限

アーカイブ入力には、次の上限を適用する。

| リソース | 上限 |
| --- | ---: |
| ZIP ファイル | 4 GiB |
| アーカイブメンバー | 50,000 |
| アーカイブ内で宣言された展開後の内容の合計サイズ | 8 GiB |
| 一つの会話 JSON メンバー | 64 MiB |
| すべての会話 JSON メンバー | 2 GiB |
| メンバーの展開後サイズと圧縮サイズの比率 | 50:1 |
| 会話 | 100,000 |
| 選択中の分岐のノード | 100,000 |
| JSON の入れ子 | 64 階層 |

共通の [応答とページ分割の上限](cli-json-contract.md#リソース制限) も適用する。

## 出力の取り扱い

記録された内容は、自動で隠蔽せずに返す。\
内容には秘密の値が含まれることがある。\
保存する内容と外部への共有は呼び出し側が決める。\
[内容の安全な扱い](cli-json-contract.md#内容の安全な扱い) を参照する。

<a id="保守者向けのアダプターの動作"></a>

## アダプターの仕様（保守者向け）

OpenAI は、エクスポートの取得方法と、ZIP にチャット履歴が含まれることを文書化している。\
内部の会話 JSON グラフは、安定した API として文書化されていない。\
そのため、正規化に使う内部メンバー名とフィールドの互換性は、アダプターで確認する。

これらの規則を変えるときは、共通の [アダプターの保守上の制約](architecture.md#プロバイダーアダプターの保守) に従う。

<a id="アーカイブの検証"></a>
<a id="zip-の安全性検査"></a>

### アーカイブの読み取り

#### ZIP ファイルの検査

アダプターは、設定されたパスを一つの通常ファイルとして開く。\
ZIP は、メンバーをディスクに展開せずに読む。

#### アーカイブメンバーの読み取り

**メンバーの検査**

次のメンバーを拒否する。

- 絶対パス、ディレクトリトラバーサル、バックスラッシュ、ドライブプレフィックス付きのパスを持つメンバー。
- 名前が重複するメンバー。
- 暗号化されたメンバー。
- シンボリックリンクと、その他の特殊な種類のメンバー。

<a id="アーカイブメンバーと会話の識別"></a>
<a id="会話の検出とソースの識別"></a>

**会話 JSON の選択**

デコーダーは、`conversations.json` と番号付きの `conversations-*.json` メンバーを、メンバー名による決まった順序で読み取る。

### ソース情報の生成

<a id="識別と検証"></a>

#### 識別情報

名前付きソースインスタンスは、明示的に選択したアーカイブの範囲を識別する。\
そのインスタンス内では、各プロバイダー固有の会話 ID が、一つの論理ソースと `source_ref` を決める。

一貫した `id` または `conversation_id` をプロバイダー固有の会話識別子として受け付け、曖昧な重複は拒否する。\
パスとアーカイブメンバー名は場所を示すものであり、会話の識別子ではない。

ZIP を新しいエクスポートで置き換えても会話の識別子は維持できるが、スナップショットと検証済みバージョンは変わる可能性がある。

<a id="変更検出用のバージョンヒント"></a>

#### バージョンヒント

ZIP 全体の SHA-256 が、`snapshot_hash` のバージョンヒントとなる。\
同じスナップショットに含まれる会話は、このヒントを共有する。

<a id="やり取り時刻の分類"></a>
<a id="ソースの最後のやり取りの時刻"></a>

#### 最後のやり取りの時刻

**時刻の計算**

`last_interaction_at` には、同じ分岐にある、認識できる `user` と `assistant` のテキストまたはマルチモーダルテキストのメッセージ、およびツールロールの結果の `create_time` を使う。\
数値の Unix 秒を正確に UTC の時刻へ変換する。\
再開後のやり取りも含めて、最も遅い値を採用する。

**計算から除外する記録**

次の値や記録では、`last_interaction_at` を進めない。

- アシスタントの `thoughts` と `reasoning_recap`。
- 別の分岐。
- 会話の `update_time`。
- ZIP ファイルの更新時刻。

**時刻を確定できない場合**

次の場合は、フィールドを省略する。

- 分岐が不正である。
- やり取りの可能性がある未知の記録がある。
- やり取りの時刻が欠落しているか、不正である。
- やり取りがない。

`list` は、該当する会話の件数を一つの省略理由にまとめる。

<a id="イベントの正規化"></a>

### イベントの生成

<a id="会話経路とイベントの正規化"></a>
#### 会話経路の選択

`events` では、次の順序で選択中の分岐を取り出す。

1. 会話の現在のノードから開始する。
2. 親リンクをたどってルートへ進む。
3. その経路を反転し、対応する観測を時系列順に出力する。

選択中の経路にないノードは、`non_active_branch` として省略する。

選択中のノードの欠落、親の循環、利用できないグラフがある場合は、`unsupported_format` を返す。\
順序を作り出したり、報告せずに分岐を短縮したりしない。

#### 種別固有の変換

以下の節では、対応するイベントの種別ごとに変換方法を説明する。

選択中の経路にある未知のノードや内容は、`unknown_node` として報告する。\
残りに有用なイベントがあれば `partial` を返し、安全に使えるイベントが一つもない観測は `unsupported` を返す。

##### メッセージイベント

`user` と `assistant` のメッセージに含まれるテキストとマルチモーダルテキストの文字列部分を、メッセージイベントに変換する。

##### ツール結果イベント

**本文**

ツールロールの結果は、対応する形式のテキスト部分を独立した結果として保持する。

**呼び出しとの対応**

`correlation_state: unmatched` と、それに対応する省略理由を返す。\
受け付ける構造には、安定した呼び出しと結果の関係がない。\
グラフ上の親や、記録が隣り合っていることから対応付けを推測しない。

**成否**

`outcome: unknown` と、それに対応する省略理由を返す。

#### 日時フィールドの設定

元のメッセージの `create_time` を使って、`recorded_at` を設定する。\
値が欠落または不正な場合は、`event_time_omitted` を付けて `events` を `partial` にする。

<a id="内容の検証"></a>

### 検証済みバージョンの算出

`verify` は、ZIP 全体をストリーム処理して内容を検証する。\
パスを含まない証拠名 `archive/export.zip` と、共通の `provider-content-v0` アルゴリズムを使う。

## 互換性の根拠

次の公式資料に、エクスポートと、その中の会話ファイルについて記載されている。

- [Exporting your ChatGPT history and data](https://help.openai.com/en/articles/7260999-how-do-i-export-my-data) には、エクスポートの申請とダウンロードの手順、および ZIP にチャット履歴が含まれることが記載されている。
- [Exporting data from a ChatGPT Edu workspace](https://help.openai.com/en/articles/20001279) には、エクスポート履歴ファイルとして `conversations.json` または番号付きの会話 JSON ファイルが示されている。

これらの参照先は、エクスポートの取得方法と会話履歴が存在することを示す。\
アダプターが解析する内部 JSON グラフを保証するものではない。
