# Claude Code プロバイダー

> **注記:** [英語版](../provider-claude-code.md) が正式版である。
> この日本語版は参考訳である。
> 内容に差異がある場合は英語版を優先する。

この文書では、`claude` アダプターで保存済みのセッション記録を読み取る方法と、出力の読み方を説明する。\
アダプターは、Claude Code を起動せずに記録を直接読み取る。

共通の `v2` JSON フィールドは [CLI 仕様](cli-json-contract.md) を参照する。

## 利用手順

<a id="claude-code-のルートの指定"></a>

<a id="claude-code-のルートを選ぶ"></a>

### 1. 記録の保存場所を選ぶ

読み取り対象には、Claude Code の設定ディレクトリを指定する。\
プロジェクトディレクトリや個別のトランスクリプトは指定しない。

保存場所は、次の優先順位で選ぶ。

1. 明示的な `--root`。
2. 設定されたソースインスタンス。
3. `CLAUDE_CONFIG_DIR`。
4. 公式資料に記載された既定値 `~/.claude`。

以下の方法から、保存場所の指定方法を選ぶ。

#### プロバイダーの設定を使う

Claude Code の既定の設定ディレクトリは、`CLAUDE_CONFIG_DIR` で上書きできる。

明示的なルートや設定済みのインスタンスがなければ、`CLAUDE_CONFIG_DIR` を使う。\
この環境変数が設定されていなければ、`~/.claude` を使う。

この場合は、ルートを指定せずにセッションを一覧にする。

```sh
agent-sessions list --provider claude
```

#### コマンドで指定する

`--root` で保存場所を指定し、セッションを一覧にする。

```sh
agent-sessions list --provider claude --root /fictional/claude-root
```

#### 設定ファイルで指定する

[設定ファイル](cli-json-contract.md#設定) に、名前付きソースインスタンスを追加する。\
たとえば、次のように指定する。

```json
{
  "schema_version": "v1",
  "sources": [
    {
      "id": "claude-records",
      "provider": "claude",
      "root": "/fictional/claude-root"
    }
  ]
}
```

その後、設定済みのインスタンスにあるセッションを一覧にする。

```sh
agent-sessions list --provider claude --source-instance claude-records
```

### 2. セッションを読み取る

`list` の結果から、読み取るセッションの `identity.source_ref` を次のプレースホルダーにコピーする。\
`--root` を使った場合は、この操作と後続のソース操作にも同じルートを渡す。

```sh
agent-sessions events --root /fictional/claude-root '<source_ref from list>'
```

プロバイダーの設定または設定済みのインスタンスを使う場合は、このコマンドの `--root` を省略する。

## 対応形式

やり取りの時刻を判定できる版と、イベントの変換や形式の検証に対応する版は異なる。

| 操作 | 対応する版と条件 |
| --- | --- |
| `list`、`show`: やり取りの時刻 | 確認済みの版 `2.1.177`、`2.1.228`、`2.1.260`。加えて、すべての行が既知の構造を保つ場合は、構文上有効な `2.1.260` 以降の版も受け付ける。版の上限は設けない。 |
| `events`、`verify`: イベントの変換と形式の検証 | `2.1.177`、`2.1.228`、`2.1.260` で確認済みの内部トランスクリプト JSONL の構造。その他の版では完全な結果とはしない。 |

Claude Code はトランスクリプトの保存場所を文書化しているが、各行の内部構造はリリース間で変わる可能性がある。\
アダプターは、未確認の構造を完全な結果として受け入れない。\
やり取りの時刻を新しい版でも読み取れることによって、`events` や `verify` で検証済みとする版は増えない。

やり取りの可能性がある未知の行や、利用できない時刻がある場合、ソースの時刻は出さない。\
詳しい規則は [ソースの最後のやり取りの時刻](#ソースの最後のやり取りの時刻) を参照する。

## 出力の読み方

### 取得したデータ

`data` に入る情報は、操作によって異なる。

<a id="サブエージェントの記録の制限"></a>

#### ソース情報

`list` と `show` は、セッションのソース情報を返す。\
最後のやり取りの時刻を確定できる場合は、`last_interaction_at` を含む。

アダプターはサブエージェントの記録を認識するが、独立したソースとして公開しない。\
保存場所は [サブエージェントの記録](#サブエージェントの記録)、制限の理由は [識別情報](#識別情報) を参照する。

#### イベント

`events` は、対応するメッセージ、ツール呼び出し、ツール結果、プロバイダーのエラーを返す。

ツールの入力と結果は、それぞれ全体を 64 KiB 以内に制限する。

#### 検証済みバージョン

`verify` は、主トランスクリプトを対象とする検証済みバージョンを返す。

<a id="不完全な結果と失敗の扱い"></a>

<a id="不完全な観測と入力上限"></a>

### 処理の状態

#### 状態を示す status

安全に読み取って表現できた内容に応じて、次の状態を返す。

| 条件 | 状態 |
| --- | --- |
| 安全に読み取った内容を完全に表現できた | `complete` |
| 省略はあるが、有用な内容を得られた | `partial` |
| ソースは認識できたが、安全に利用できる有用な内容を得られなかった | `unsupported` |
| I/O、ルート内にあることの検査、ファイルの置換競合、リソースに関する処理が失敗した | `error` |

#### 省略理由を示す omissions

取得できない内容や未対応の構造は、`omissions` で報告する。

#### 失敗の原因を示す error

I/O やリソース処理などの失敗は、構造化された `error` で説明する。\
フィールドとコードは、共通の [エラー仕様](cli-json-contract.md#エラーと終了コード) を参照する。

## 入力の上限

プロバイダーの入力には、次の上限を適用する。

| 入力 | 上限 |
| --- | --- |
| 記録ファイル | 64 MiB |
| セッション識別子を確認するために読む先頭部分 | 1 MiB |
| JSONL の一行 | 1 MiB |
| サイドカー | 1 MiB |
| 検出するファイル | 100,000 個 |
| 正規化するイベント | 100,000 件 |

これらは、公開する [応答とページ分割の上限](cli-json-contract.md#リソース制限) に加えて適用する。

## 出力の取り扱い

記録された内容は、自動で隠蔽せずに返す。\
内容には秘密の値が含まれることがある。\
保存する内容と外部への共有は呼び出し側が決める。\
[内容の安全な扱い](cli-json-contract.md#内容の安全な扱い) を参照する。

<a id="保守者向けのアダプターの動作"></a>

## アダプターの仕様（保守者向け）

以下の節では、記録の識別方法と、内容の変換規則を説明する。\
内部の JSONL 構造はプロバイダーの版に依存し、安定した公開フィールドではない。\
これらの規則を変えるときは、共通の [アダプターの保守上の制約](architecture.md#プロバイダーアダプターの保守) に従う。

<a id="記録の検出とソースの識別"></a>

<a id="検出識別内容のバージョン"></a>

### 記録の読み取り

アダプターは `projects` を決まった順序で走査する。\
サイズ制限内で、プロバイダーのルート内にある通常ファイルだけを受け付ける。\
シンボリックリンクと特殊ファイルを拒否し、内容を開くときにファイルとルートの同一性を再確認する。

#### 主トランスクリプト

主セッションのトランスクリプトは、設定ルート下の `projects/<project>/<session-id>.jsonl` に保存される。

<a id="サブエージェントの記録の扱い"></a>

<a id="サブエージェントの場所とサイドカー"></a>

#### サブエージェントの記録

**保存場所**

Claude Code は、サブエージェントのトランスクリプトを `projects/<project>/<session-id>/subagents/agent-<agent-id>.jsonl` に保存すると文書化している。

確認に使った配布物は、これらの記録の隣にメタデータのサイドカーも書き出す。

**検査規則**

アダプターは、このルート内のパスにある記録だけを認識する。\
ファイルが通常ファイルで、ルート内にあることを同じ方法で検査する。\
読み取るサイドカーにもサイズ制限を設ける。\
サイドカーの欠落、孤立、不正な形式、サイズ超過は明示的に報告する。

独立したソースとして公開しない理由は、[識別情報](#識別情報) を参照する。

### ソース情報の生成

#### 識別情報

プロバイダー固有のセッション識別子は、トランスクリプト内の検証済み `sessionId` フィールドから取得する。\
ファイル名は整合性の確認にだけ使う。\
トランスクリプトを別のプロジェクトの保存場所へ移動しても、`source_ref` は変わらない。

**重複した記録**

同じプロバイダー固有のセッション識別子を含む記録が複数ある場合、アダプターはどのコピーが現在のものかを推測しない。\
`list` と `show` は曖昧さを報告し、内容に関する操作は `unsupported` を返す。

**サブエージェントの識別**

対応する形式では、サブエージェントの記録を独立した論理ソースとして公開しない。\
確認済みのトランスクリプトとサイドカーには、プロバイダーが定義する独立したサブエージェントの識別フィールドがない。\
ファイル名から識別子を作ったり、パスから関係を導いたりすると、共通の識別仕様に反する。

<a id="変更検出用のバージョンヒント"></a>

#### バージョンヒント

一覧のバージョンヒントは、記録ファイルの数、サイズ、変更時刻をドメイン分離してハッシュ化したものである。\
ヒントと検証済みバージョンの違いは、[変更検出と内容の検証](architecture.md#変更検出と内容の検証) を参照する。

<a id="ソースの最後のやり取りの時刻"></a>

<a id="やり取り時刻の分類"></a>

#### 最後のやり取りの時刻

対応するユーザーとアシスタントのメッセージ行またはツール行の時刻のうち、最も遅いものを `last_interaction_at` とする。

**対応する版と構造の条件**

やり取りの時刻は、確認済みの版に加えて、すべての行が既知の構造を保つ場合は、構文上有効な `2.1.260` 以降の版でも読み取る。\
この前方互換の条件に版の上限は設けない。\
これによって、`events` や `verify` で検証済みとする版は増えない。

**記録の種類ごとの時刻判定**

各記録がソースの時刻に与える影響は、次のとおりである。

| 記録 | 時刻への影響 |
| --- | --- |
| 対応するユーザーまたはアシスタントのメッセージ行やツール行 | 最後のやり取りの時刻の候補にする。 |
| 後述する、既知の非対話の添付行 | 時刻を進めない。 |
| `away_summary` と `informational` を含む、対応する非対話のシステム行 | 時刻を進めない。 |
| 管理用行 | 時刻を進めない。 |
| プロバイダー API エラー | 時刻を進めない。 |

次の種類の添付行は、構造から非対話の観測と判定できる。

- `agent_listing_delta`
- `command_permissions`
- `deferred_tools_delta`
- `diagnostics`
- `edited_text_file`
- `opened_file_in_ide`
- `plan_mode`
- `plan_mode_exit`
- `selected_lines_in_ide`
- `skill_listing`
- `task_reminder`

**時刻を確定できない条件**

次の場合は、ソースの時刻を出さない。

- 添付行が上記以外の種類である。\
  コマンド待機の可能性があるものを含め、やり取りを表すか確定できない。
- 時刻が欠落しているか、不正である。
- やり取りの可能性がある未知の行やブロックがある。
- 版が不正、または `2.1.260` より古い未確認の版である。
- 同じセッション識別子を持つトランスクリプトが複数ある。

<a id="イベントの正規化"></a>

<a id="ツール呼び出し結果イベント時刻"></a>

### イベントの生成

<a id="読み取る行と省略する内容"></a>

<a id="メッセージと省略する内容"></a>

#### 対象行の選択

アダプターは、確認済みの版の `user`、`assistant`、`system`、`attachment` 行を受け付ける。\
公開するユーザーとアシスタントのテキスト、および後述するツールとエラーの記録を正規化する。

既知の管理用行は公開する観測には含めず、無視する。\
次の内容は省略として報告する。

- 未知の行と未知の内容ブロック。
- 添付ファイル。
- 推論ブロック。
- 内部ユーザーメタデータ。
- 未対応のシステム観測。

#### 種別固有の変換

対応するイベントの種別ごとに、次の規則で変換する。

##### メッセージイベント

ユーザーとアシスタントのテキストを、メッセージイベントに変換する。

<a id="ツール呼び出しの名前分類入力"></a>

##### ツール呼び出しイベント

**名前**

アダプターは、各 `tool_use` 呼び出しに記録された `name` を返す。

**カテゴリ**

公開カテゴリは `shell`、`filesystem`、`file_change`、`mcp`、`tool` とする。

**操作**

既知のツール名は `execute`、`read`、`search`、`write`、`edit` に対応付け、その他の呼び出しは `invoke` とする。

**入力**

アダプターは、オブジェクト形式の `input` を返す。\
入力を取得できたかどうかは、次の状態で示す。

| 記録された入力 | 状態 |
| --- | --- |
| 空のオブジェクトを含む、オブジェクト形式の値 | `available` |
| 項目なし | `absent` |
| 未対応の値 | `unsupported` |

**呼び出し ID**

ツール呼び出し ID は、セッション識別子とプロバイダーの相関識別子から決定的に生成する、アダプターが所有するハッシュである。

<a id="ツール結果の本文"></a>

<a id="呼び出しと結果の対応関係"></a>

<a id="ツールの成否"></a>

##### ツール結果イベント

**本文**

文字列とテキストブロックの `tool_result` 本文は、行を選別せずに返す。\
複数のテキストブロックは、順序を保った JSON 配列にする。\
非テキスト部分を除外した場合は、省略を報告し、読めるテキストを残す。

**呼び出しとの対応**

結果は、明示された `tool_use_id` の値だけで呼び出しと関連付ける。\
この値で一意に対応できれば、記録の順番が前後していても結び付ける。

呼び出しと結果の重複、対応先がない結果、保存済み結果のない呼び出しは `complete` にしない。\
読める本文は保持する。

**成否**

結果の `outcome` は、確認済みの `tool_result.is_error` の意味に従って判定する。

| `tool_result.is_error` | 成否 |
| --- | --- |
| 項目なし、または `false` | 成功 |
| `true` | 失敗 |
| 不正な値 | 不明。本文は保持する。 |

<a id="プロバイダーのエラー"></a>

##### プロバイダーエラーイベント

明示されたプロバイダー API エラーを正規化する。

<a id="イベント一件の日時"></a>

#### 日時フィールドの設定

各イベントは、元のトランスクリプト行の日時を使う。\
そのため、同じ行から生成されたイベントは `recorded_at` を共有する。

<a id="内容の検証"></a>

### 検証済みバージョンの算出

**検証する記録**

検証では、入力の上限内の主トランスクリプトを、共通の `VerifiedVersion` 仕様に従ってハッシュ化する。\
主ソースの検証証拠は主トランスクリプトだけである。\
そのため、サブエージェントのトランスクリプトやサイドカーを変更しても、主ソースの検証済み内容のバージョンは変わらない。

**検証証拠の名前**

主トランスクリプトには、パスを含まない証拠名 `transcript/primary.jsonl` を使う。

## 互換性の根拠

<a id="保存場所とライフサイクルに関する公式資料"></a>

### 保存場所の根拠

次の公式資料に、記録の保存場所と、ライフサイクルに関する入力項目が記載されている。

- [Sessions](https://code.claude.com/docs/en/sessions) には、トランスクリプトの保存と `projects/<project>/<session-id>.jsonl` の場所が記載されている。
- [Environment variables](https://code.claude.com/docs/en/env-vars) には、`CLAUDE_CONFIG_DIR` と既定の設定ディレクトリの動作が記載されている。
- [Hooks](https://code.claude.com/docs/en/hooks) には、ライフサイクル入力の `session_id` と `transcript_path` が記載されている。
- [Subagents](https://code.claude.com/docs/en/sub-agents) には、サブエージェントのトランスクリプトの場所が記載されている。

これらの参照先は、場所とライフサイクルに関する仕様を示す。\
内部 JSONL エントリの構造を安定した公開 API にするものではない。

<a id="バージョン別の確認内容"></a>

### 内部形式の確認

互換性は、次の資料と方法で確認している。

| 版 | 確認内容 |
| --- | --- |
| `2.1.177` | プロバイダーが所有する非公開の記録を読み取り専用で確認し、独立して作成した合成フィクスチャでカバーしている。確認したのは構造上の性質だけであり、非公開の内容や識別子はこのリポジトリへコピーしていない。 |
| `2.1.228` | 公式の Claude Code 配布物と、文書化されたトランスクリプト、フック、ステータスライン、サブエージェントの場所に関する仕様。 |
| `2.1.260` | 署名済みの公式配布物を実行せずに、行の書き出し構造を調べた。実際のトランスクリプトはフィクスチャに使っていない。 |

これらの確認は、すべての行の構造を検証するものではない。\
未知の行やブロックがある場合は、引き続き `complete` にしない。

<a id="読み取り専用動作の検証"></a>

### 読み取り専用性の確認

合成統合テストでは、代表的な `list`、`show`、`events`、`verify` 操作の前後で、プロバイダーのツリーを比較する。\
比較するのは、ファイル集合、種類とモード、サイズ、変更時刻、内容ハッシュである。
