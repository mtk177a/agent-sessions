# ChatGPT Data Export プロバイダー

> **注記:** [英語版](../chatgpt.md) が正式版です。
> この日本語版は参考訳です。
> 内容に差異がある場合は英語版を優先します。

`chatgpt` アダプターについて、既存の ChatGPT Data Export ZIP の指定方法と、公開する会話と分岐の範囲を確認する。\
保守者向けの節では、アーカイブのデコードと互換性の根拠を説明する。\
共通の `v2` JSON フィールドは [CLI 仕様](cli-json-contract.md) で定義する。

## エクスポート ZIP を選ぶ

ChatGPT の **Settings → Data Controls → Export Data** から、または OpenAI の Privacy Portal からエクスポートを請求し、OpenAI が説明する利用可能期間内にダウンロードする。

`agent-sessions` はエクスポートを請求、ポーリング、検出、ダウンロードしない。\
各アーカイブは、`--provider chatgpt` と `--root` を使うか、明示的な設定エントリを追加して、名前付きソースインスタンスとして選択する必要がある。

```sh
agent-sessions list --provider chatgpt --source-instance chatgpt-export --root /fictional/chatgpt-export.zip
agent-sessions events --root /fictional/chatgpt-export.zip '<source_ref from list>'
```

```json
{
  "schema_version": "v1",
  "sources": [
    {
      "id": "chatgpt-personal",
      "provider": "chatgpt",
      "root": "/fictional/chatgpt-export.zip"
    }
  ]
}
```

ルートは正確な ZIP ファイルであり、ディレクトリではない。\
このプロバイダーには環境変数によるルートも既定のルートもない。

## 会話、分岐、内容

`events` は、選択中の会話経路にあるユーザーとアシスタントのメッセージから、テキストとマルチモーダルテキストの文字列部分を返す。\
ほかの分岐は省略し、`non_active_branch` を報告する。

ツールロールの読める結果も返すが、呼び出しとの対応と成否は確定できないため、省略を報告する。\
未知の内容や利用できない会話経路がある場合も、その不完全さを報告する。

発言と道具の結果は共通の上限に従い、自動で内容を隠さずに返す。\
読める文字列は保持し、非テキスト部分や未対応の部分を除外したことは報告する。\
秘密の値が含まれ得るため、保存と外部への共有は利用側が決める。

### やり取りの時刻

`list` と `show` は、選択中の会話経路から最後のやり取りの時刻を確定できる場合、`last_interaction_at` を公開する。\
確定できない場合はフィールドを省略し、`source_time_unavailable` を付けて `partial` を返す。\
出力するメッセージイベントは、それぞれの `create_time` を `recorded_at` として報告する。\
値が欠落または不正な場合は、`event_time_omitted` を付けて `events` を `partial` にする。

## アーカイブの上限

現在の入力制限は次のとおりである。

| リソース | 制限 |
| --- | ---: |
| ZIP ファイル | 4 GiB |
| アーカイブメンバー | 50,000 |
| 宣言された非圧縮アーカイブ内容 | 8 GiB |
| 一つの会話 JSON メンバー | 64 MiB |
| すべての会話 JSON メンバー | 2 GiB |
| 非圧縮と圧縮のメンバー比率 | 50:1 |
| 会話 | 100,000 |
| アクティブブランチのノード | 100,000 |
| JSON の入れ子 | 64 階層 |

これらはアーカイブ入力の上限であり、共通の [応答とページ分割の上限](cli-json-contract.md#リソース制限) も適用する。\
ZIP はメンバーをディスクに展開せずに読む。

## 保守者向けのアダプターの動作

OpenAI は、Data Export の請求方法と、ダウンロードした ZIP にチャット履歴が含まれることを文書化している。\
OpenAI はアーカイブ内の会話 JSON グラフを安定した API として文書化していないため、正規化に使用する内部メンバー名とフィールドはすべてアダプターが所有する互換性境界に残す。

これらの規則を変えるときは、共通の [アダプターの保守上の制約](architecture.md#プロバイダーアダプターの保守) に従う。

### 識別と検証

アーカイブとその会話は異なる識別子を持つ。

- 名前付きソースインスタンスは、明示的に選択されたアーカイブの境界を識別する。
- 各プロバイダー固有の会話 ID が、一つの論理ソースと `source_ref` を決める。
- ZIP 全体の SHA-256 は、そのスナップショットに含まれる会話で共有する `snapshot_hash` のバージョンヒントである。
- `verify` は、パスを含まない共通の `archive/export.zip` 証拠名を使って ZIP 全体をストリーム処理し、既存の `provider-content-v0` アルゴリズムを使用する。

ZIP を新しいエクスポートで置き換えても会話の識別子は維持できるが、スナップショットと検証済みバージョンは変わる可能性がある。\
パスとアーカイブメンバー名は場所を示すものであり、会話の識別子ではない。

### 会話経路とイベントの正規化

`events` では、アダプターは会話の現在のノードから開始し、親リンクをたどってルートへ進み、そのチェーンを反転して、対応する観測を時系列順に出力する。\
`user` と `assistant` のメッセージに含まれるテキストとマルチモーダルテキストの文字列部分は、正規化されたメッセージイベントになる。

アクティブなチェーンの外側にあるノードは `non_active_branch` として省略する。\
ツールロールの結果は、対応済みの文章形式を独立した結果として保持し、`correlation_state: unmatched`、`outcome: unknown` と省略理由を返す。\
受け付ける形式には安定した呼び出しと結果の関係がないため、グラフ上の親や隣接する順番から対応付けを推測しない。\
アクティブな未知のノードや内容は `unknown_node` として報告し、残りに有用なイベントがあれば `partial` を返し、安全に使用できるイベントが一つもない観測は `unsupported` を返す。\
アクティブなノードの欠落、親の循環、利用できないグラフがある場合は、順序を作り出したりブランチを黙って短縮したりせず、`unsupported_format` を返す。

### アーカイブメンバーと会話の識別

互換性デコーダーは、`conversations.json` と番号付きの `conversations-*.json` メンバーをメンバー名の決定的な順序で読み取る。\
一貫した `id` または `conversation_id` をプロバイダー固有の会話識別子として受け付け、曖昧な重複は拒否する。

### やり取り時刻の分類

`last_interaction_at` には、同じ経路にある、認識できる `user` と `assistant` のテキストまたはマルチモーダルテキストのメッセージ、およびツールロールの結果の `create_time` を使う。\
数値の Unix 秒を正確に UTC の時刻へ変換し、再開後のやり取りも含めて最も遅い値を採用する。\
アシスタントの `thoughts` と `reasoning_recap`、別の分岐、会話の `update_time`、ZIP ファイルの更新時刻ではフィールドを進めない。\
経路が不正な場合、やり取りの可能性がある未知の記録、やり取りの時刻の欠落・不正値、またはやり取りがない場合はフィールドを省略する。\
`list` は該当する会話の件数を一つの省略理由にまとめる。

### アーカイブの検証

アダプターは設定されたパスを一つの通常ファイルとして開き、メンバーを展開しない。\
絶対パス、ディレクトリトラバーサル、バックスラッシュ、ドライブプレフィックス付きのメンバーパス、重複したメンバー名、暗号化されたメンバー、シンボリックリンク、その他の特殊なメンバー種別を拒否する。

不正な ZIP データ、不正な JSON、重複メンバー、安全でないメンバー、ソースの置換、リソース制限の失敗には、それぞれ異なる構造化エラーコードを付ける。\
認識はできるが互換性のない JSON 形式は、不正な入力ではなく `unsupported` として返す。

## 互換性の根拠

- [How do I export my ChatGPT history and data?](https://help.openai.com/en/articles/7260999-how-do-i-export-my-data) には、エクスポートの請求とダウンロードの手順が記載され、ZIP にチャット履歴が含まれることが説明されている。
- [How can I view my conversation history in a ChatGPT EDU workspace?](https://help.openai.com/en/articles/20001279) には、エクスポート履歴ファイルとして `conversations.json` または番号付きの会話 JSON ファイルが示されている。

これらの参照先は、エクスポートの取得方法と会話履歴が存在することを示す。\
アダプターが解析する内部 JSON グラフを保証するものではない。
