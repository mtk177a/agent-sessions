# CLI JSON 仕様

> **注記:** [英語版](../cli-json-contract.md) が正式版である。
> この日本語版は参考訳である。
> 内容に差異がある場合は英語版を優先する。

この文書は、`agent-sessions` を呼び出すスクリプトや、JSON 出力を解釈する処理を実装するときに使う。\
インストールと最初の読み取りは [README](../../README.ja.md) を参照する。\
プロバイダー固有のルート、対応形式、入力上限は、[Codex](provider-codex.md)、[Claude Code](provider-claude-code.md)、[ChatGPT Data Export](provider-chatgpt-export.md) に記載する。

## コマンドの呼び出し

### コマンド構文

コマンドの構文は次のとおりである。

```text
agent-sessions list [--config PATH] [--provider ID [--source-instance ID] [--root PATH]] [--repository PATH] [--limit N] [--cursor TOKEN]
agent-sessions show [--config PATH] [--root PATH] <source-ref>
agent-sessions events [--config PATH] [--root PATH] [--limit N] [--cursor TOKEN] <source-ref>
agent-sessions verify [--config PATH] [--root PATH] <source-ref>
```

### オプション

オプションの意味と対象のコマンドを次に示す。

| オプション | 対象 | 意味 |
| --- | --- | --- |
| `--config PATH` | 全操作 | 指定した厳密な JSON 設定ファイルを読む。 |
| `--provider ID` | `list` | 一つのプロバイダーを選ぶ。省略時は利用可能なプロバイダーをまとめる。 |
| `--source-instance ID` | `--provider` を指定した `list` | 名前付きの保存場所やエクスポートを一つ選ぶ。 |
| `--root PATH` | 全操作。`list` では `--provider` が必要 | 今回の呼び出しでプロバイダー単位のルートを上書きする。 |
| `--repository PATH` | `list` | ローカル Git リポジトリと、その linked worktree を選ぶ。提供元の記録ルートとは独立した指定である。 |
| `--limit N` | `list`、`events` | ページサイズを指定する。既定 50、最大 100。 |
| `--cursor TOKEN` | `list`、`events` | 前のページが返した不透明なカーソルで続きを取得する。 |

`list --source-instance` と `list --root` のオプションには、ソースインスタンス ID とルートがプロバイダー単位で管理されるため、`--provider` が必要である。

### ソース参照の指定規則

`<source-ref>` には、`list` 応答の `identity.source_ref` をコピーし、ファイルパスから作らない。\
フラグは位置引数のソース参照より前に置く。

明示したルートから一覧にしたソースを読む場合は、後続の操作にもそのルートを渡すか、インスタンスを設定する。\
ソース参照はルートのパスを含まない。\
ルートの選択は [読み取り対象の設定](#読み取り対象の設定)、ページ分割は [全ページを取得する](#全ページを取得する) を参照する。

### ローカル Git リポジトリのセッションを探す

```sh
agent-sessions list --repository /fictional/project
```

`PATH` には、存在するリポジトリのルート、worktree、またはサブディレクトリを指定する。\
コマンドで指定した相対パスは、呼び出し時のディレクトリから解決する。\
`PATH` 上に Git があり、`rev-parse --path-format=absolute` と `worktree list --porcelain -z` に対応している必要がある。\
対象、Git 実行ファイル、または対象の登録一覧を利用できない場合は、`invalid_repository` と終了コード `2` を返す。

正規化した Git 共通管理ディレクトリを比較する。\
リモート URL、ブランチ、コミットによって独立した clone を統合せず、入れ子のリポジトリも個別に解決する。\
記録された作業場所が一つでも指定リポジトリに所属すれば、そのソースは一致する。\
複数の観測が一致してもソースは 1 件とし、イベントには対応する会話全体を引き続き含める。

絞り込みは、ソース参照による並べ替えとページ分割の前に行う。\
ページ間では、リポジトリ、記録ルート、設定、ソースのスナップショットを変えない。\
`data.repository.common_dir` は検索対象の解決結果であり、安定したソース識別子ではなく、ローカルの場所を示す。

所属不明の候補は `data.sources` から除外し、scope が `repository` の `repository_membership_unknown` に件数を示す。\
任意のトークン `reason` が各グループの理由を示し、`count` はパス数ではなく候補数を数える。\
複数の不足がある候補も一度だけ数え、その理由の一つを示す。\
件数は各ページで候補全体を対象とし、ページ分割の省略とは区別する。\
一致したソースに別の不足が残る場合は、そのソースを含めたうえで、同じく理由ごとに `repository_evidence_incomplete` を返す。\
いずれの省略も、最後のページを含めて検索結果を `partial` にする。\
空の partial 結果から、該当する会話が存在しないとは判断できない。

理由には `directory_unavailable`、`invalid_directory`、`git_unavailable`、`mapping_unavailable`、`conflicting_evidence`、`history_unavailable`、`ambiguous_artifact`、`unsupported_directory_record`、`invalid_directory_record`、`unsupported_provider`、`directory_limit`、`git_lookup_limit` がある。\
検出、ソース時刻、その他の既存の省略は、ソースが絞り込みで除外されても応答に残る。

## 読み取り対象の設定

### 設定ファイル

#### ファイルの選択

既定のパスは、`os.UserConfigDir` が返すプラットフォームのユーザー設定ディレクトリ下にある `agent-sessions/config.json` である。\
既定のファイルがないことは有効であり、ディレクトリやファイルの作成も引き起こさない。

`--config` は明示的な設定ファイルを選択する。\
そのファイルを作成または更新するものではない。

#### 設定の構造

設定は厳密な JSON 形式で、独立した `schema_version: v1` を使う。

#### 設定値の制約

プロバイダー ID とソースインスタンス ID は `[a-z][a-z0-9-]{0,62}` に一致する。\
一つのプロバイダー内でソースインスタンス ID は一意であり、ルートは絶対パスで、未知のフィールドは拒否する。

#### 設定例

次の例では、独立した二つの Codex ホームを設定する。

```json
{
  "schema_version": "v1",
  "sources": [
    {"id": "codex-one", "provider": "codex", "root": "/fictional/codex-one"},
    {"id": "codex-two", "provider": "codex", "root": "/fictional/codex-two"}
  ]
}
```

`root` を実際の絶対パスに置き換える。\
`id` は安定した名前を選び、変更するとソース参照も変わる。

設定したインスタンスの一つを `--source-instance` で選ぶ。

```sh
agent-sessions list --provider codex --source-instance codex-one
```

### ルートの解決

#### 選択の優先順位

解決の優先順位は次のとおりである。

1. `--root` によるコマンドライン上書き。
2. 一致するユーザー設定。
3. プロバイダーの環境変数。
4. プロバイダーの既定値。

#### 保存場所へのアクセス

ルートの選択とアクセスには、次の規則がある。

| 条件 | 動作 |
| --- | --- |
| `list` で、プロバイダーの環境変数または既定値だけで選ばれたルートが存在しない。 | そのルートのソースインスタンスを追加しない。 |
| 明示した `--root` または設定済みのルートへアクセスできない。 | 操作はエラーを返す。 |
| プロバイダーに環境変数や既定のルートがない。 | 暗黙のソースインスタンスを追加しない。 |

このため、登録されたすべてのプロバイダーをインストールしなくても、利用可能なプロバイダーの記録を探せる。

#### プロバイダー固有の指定条件

`chatgpt` プロバイダーでは、ルートを明示的に指定する必要がある。\
ルートには、読み取る一つの Data Export ZIP を指定する。\
検索対象のディレクトリは指定しない。

## JSON 応答の構成

公開応答スキーマは安定版 `v2` である。\
同じ仕様を、実運用の Codex、Claude Code、ChatGPT Data Export アダプターが実装する。

自動処理用の仕様は JSON だけであり、人間向けの出力は実装していない。

### 応答スキーマの検証

呼び出し側は、`data` やその他のバージョン依存フィールドを解釈する前に、`schema_version` を読み取り検証しなければならない。\
この仕様を実装する呼び出し側は `v2` を受け付け、未知のメジャーバージョンを拒否する。

スキーマのメジャーバージョンを受け入れた後、呼び出し側は未知の応答フィールドを無視しなければならない。

### 共通フィールド

`list` の最小で完全な応答は次のとおりである。

```json
{
  "schema_version": "v2",
  "cli_version": "dev",
  "operation": "list",
  "status": "complete",
  "data": {
    "sources": []
  },
  "page": {
    "limit": 50,
    "has_more": false
  },
  "omissions": []
}
```

応答全体の各フィールドには、次の出現規則がある。

| フィールド | 出現規則 |
| --- | --- |
| `schema_version` | 必須。この仕様では常に `v2`。 |
| `cli_version` | 必須。実行ファイルのビルドを識別し、`dev` の場合がある。 |
| `operation` | 必須。`list`、`show`、`events`、`verify`、またはコマンドレベルエラー用の `cli` のいずれか。 |
| `status` | 必須。[結果の状態](#完全性) のいずれか。 |
| `data` | `complete` と `partial` の操作結果では必須。`unsupported` と `error` では存在しない。 |
| `page` | 成功または一部完了した `list` と `events` の結果では必須。それ以外では存在しない。 |
| `omissions` | 必須。`complete` では空、`partial` と `unsupported` では空でなく、`error` では出力処理による省略を記録する場合がある。 |
| `error` | `error` の場合だけ必須。それ以外の状態では存在しない。 |

### コマンド別のデータ

`data` オブジェクトには、要求された操作に対応するフィールドだけを含める。

| 操作 | `data` の必須フィールド |
| --- | --- |
| `list` | `sources`。空でもよいソースオブジェクトの配列。 |
| `show` | `source`。一つのソースオブジェクト。 |
| `events` | `source_ref` と `events`。空でもよい配列。 |
| `verify` | `source_ref` と `verified_version`。 |

#### `list`

`list` は `data.sources` と `page` オブジェクトを返す。\
ソースは、オフセットによるページ分割を適用する前に論理ソース参照で並べ替える。

#### `show <source-ref>`

`show` は `data.source` として、正規化した一つのソースを返す。

#### `events <source-ref>`

`events` は `data.source_ref`、順序付けられた `data.events`、`page` オブジェクトを返す。\
イベントのインデックスは 0 始まりで、プロバイダーの順序を保つ。

#### `verify <source-ref>`

`verify` は `data.source_ref` と `data.verified_version` を返す。

### ページ情報

**フィールド**

`page` オブジェクトには整数の `limit` と Boolean の `has_more` が必要である。\
`has_more` が true の場合は `next_cursor` が必要で、それ以外では存在しない。

**カーソル**

カーソルの内容は呼び出し側にとって不透明である。

現在のカーソルは `v0:` で始まる。\
このカーソル形式のバージョンは `schema_version` から独立している。

取得手順は [全ページを取得する](#全ページを取得する) を参照する。

後続ページがある場合の完全性は [status](#status) を参照する。

## 返却データの定義

### ソース

ソースは、個別に指定できる一つのセッションや会話である。\
ソースインスタンスは、それを含むプロバイダーの保存場所やエクスポートに付ける名前である。

#### 共通フィールド

各ソースには `identity`、`kind`、`relationships`、`metadata` が必要である。\
`working_directories`、`version_hint`、`last_interaction_at`、`identity.provider_native_source_id` は任意であり、その他の識別フィールドはすべて必須である。

#### 論理識別子

ソース識別子は、次の情報を分離する。

```text
provider
source instance
provider-native source ID
```

コマンドラインのソース参照は、次の形式である。

```text
as0:<provider>:<source-instance>:<source-id-fingerprint>
```

フィンガープリントは、プロバイダー固有のソース ID をドメイン分離して SHA-256 ハッシュ化したものである。\
同じ識別情報からは、常に同じ参照が得られる。\
参照には、生のプロバイダー固有 ID やファイルシステム上のパスを含めない。

`identity` オブジェクトには `provider`、`source_instance`、`provider_source_fingerprint`、`source_ref` が必要である。\
任意の `provider_native_source_id` には、出力上限内でプロバイダーが所有する論理 ID を含める。\
生の値を省略した場合でも、フィンガープリントとソース参照は利用できる。

`as0` プレフィックスとソースフィンガープリントの `v0` ドメイン区切り文字は、`schema_version` とは独立してバージョン管理する。\
公開応答スキーマが `v2` に達したというだけで、これらを変更することはない。

#### ソースの種類

ソースの `kind` は拡張可能なトークンである。\
現在出力する値は、Codex と Claude Code の記録では `session`、ChatGPT Data Export の会話では `conversation` である。\
呼び出し側は、自分が認識していない `kind` トークンをソースが使っているという理由だけで、その他は有効な `v2` 応答を拒否してはならない。

#### ソース間の関係

各関係には `kind` と `source_ref` が必要である。\
現在出力する関係種別は `parent` と `forked_from` で、どちらも明示されたプロバイダー所有の識別フィールドだけに基づく。\
安全に識別できない関係は、パスやイベント順から導出せず、アダプターが省略する。

#### バージョンヒント

存在する場合、`version_hint` には `kind` と `value` が必要で、`kind` も拡張可能である。\
継承履歴のない Codex ソースと Claude Code は安価な変更検出のために `stat_hash` を出力する。\
継承履歴を安全に解決できた Codex ソースは、採用したロールアウトの範囲に対する `content_hash` を出力する。\
ChatGPT Data Export はエクスポート ZIP 全体の SHA-256 識別子として `snapshot_hash` を出力する。\
呼び出し側は認識済みのヒントを変更検出に使ってよく、認識していないヒント種別は無視しなければならない。

#### ソースのやり取りの時刻

`last_interaction_at` がある場合、その値は末尾が `Z` の正規化された UTC の RFC 3339 時刻である。\
一つの論理ソースに記録されたユーザーまたはアシスタントのメッセージ、ツール呼び出し、ツール結果のうち、最も遅い時刻を表す。\
管理用の行、システム通知、ファイルの更新時刻は含めない。

**時刻を確定できない場合**

やり取りがない場合や、最後のやり取りの時刻を安全に確定できない場合、このフィールドはない。\
時刻を確定できない理由には、次のものがある。

- やり取りを記録した行の時刻が欠けている、または不正である。
- やり取りを含む可能性がある未知の行がある。
- プロバイダーのやり取り時刻の判定に対応していない版である。
- 読み取り対象の成果物を一意に確定できない。
- 継承履歴を解決できない。

その場合は `scope: source` の `source_time_unavailable` を追加し、`list` または `show` を `partial` にする。\
`count` で影響するソース数をまとめて示す場合がある。

**ChatGPT のアクティブな分岐**

ChatGPT Data Export では選択中の会話経路にあるやり取りを対象とし、別の分岐によってこのフィールドは進まない。

#### 記録された作業場所

`list` と `show` は、任意の `working_directories` を返すことがある。\
フィールドがない場合は、この観測が未対応であり、どのリポジトリでも作業しなかったことを意味しない。\
このオブジェクトには `state`、`locations`、`reasons` が必要で、両配列は空でもよい。\
`state` は `complete`、`partial`、`unsupported` のいずれかで、記録された作業場所の根拠を取得できた範囲を示す。\
`partial` と `unsupported` にはトークンの理由が必要で、`complete` では理由を持たない。\
取得が complete でも、実際のすべての移動が記録されたとは証明できない。

各作業場所のフィールドは次のとおりである。

| フィールド | 意味 |
| --- | --- |
| `path` | 記録された絶対ディレクトリ。短縮せず、文章から推測しない。 |
| `evidence` | `session`、`turn`、`tool`、`interaction`、`worktree`。記録された根拠の共通分類。 |
| `mapping`（任意） | 記録された worktree の対応。`original_path` と `kind` が必須で、`previous_path` は任意。種類は `git_created`、`existing`、`hook`、`unknown`。 |
| `repository`（任意） | ローカルでの解決結果。必須の `state` は `resolved` または `unknown`。 |

resolved の所属には `common_dir` と `basis` が必要で、`reason` を持たない。\
根拠は `current_git`、`git_registration`、`provider_mapping` のいずれかである。\
unknown の所属にはトークン `reason` が必要で、`common_dir` と `basis` を持たない。\
プロバイダーの結果は所属の解決を省略でき、CLI の `list` と `show` が返す作業場所を解決する。

現在の Git による解決では、最も近いリポジトリを使い、管理パスのシンボリックリンクを解決する。\
これは現在のファイルシステムの根拠であり、過去の所属の証明ではない。\
移動、検出できないパスの再利用、別環境からコピーした記録は、パスだけでは復元できない。\
利用できる根拠が矛盾する場合は、どちらかの所属を選ばず、不明とする。\
あるパスの矛盾は、同一ソース内のそのパスの別の所属判定も無効にするが、独立した場所での一致は捨てない。

worktree のルートが存在しない場合は、検索対象リポジトリに残る登録から所属を確認できる。\
この補完はルートの完全一致に限り、存在しない子ディレクトリには別の入れ子リポジトリがあった可能性が残る。\
`show` には検索対象リポジトリがないため、その登録は調べない。\
通常の Git 作成として確認したプロバイダーの対応情報は、元の場所から、存在しないルートを解決できる。\
以前の場所が記録されている場合は、それも同じリポジトリに解決できる必要がある。\
既存 worktree への移動と Hook 作成は、それだけでこの関係を確定しない。\
存在するパスの管理情報が矛盾するか利用できない場合は、削除済み worktree として補完しない。\
復元できない場所は不明のままとする。

ソースごとの異なる作業場所の観測は最大 256 件で、呼び出しごとの未照会の Git ディレクトリの確認は最大 4,096 件である。\
これを超える観測や確認は不完全として残る。\
各 Git 読み取りには 5 秒のタイムアウトと 1 MiB の標準出力上限がある。\
パスや構造上のフィールドを別の識別子へ短縮しない。

`--repository` がない場合、外側の status は従来のソースメタデータについての意味を保つ。\
この任意の観測には、`working_directories.state`、`reasons`、各 `repository.state` を確認する。\
絞り込みがある場合は、[リポジトリ検索](#ローカル-git-リポジトリのセッションを探す) の規定に従い、不確実性を外側にも反映する。\
作業場所の根拠は、ソース参照、ヒント、イベント番号、提供元内容の検証済みバージョンを変えない。\
所属解決に使う Git 管理情報は、`verify` の根拠には含まれない。\
作業場所や Git 管理パスには私的な情報が含まれ得るが、自動では秘匿化しない。

### イベント

#### 共通フィールド

各イベントには `index`、`kind`、種類に対応するデータ一つ、サイズ制限内の `metadata` が必要である。

#### 記録された日時

イベントは `time_state` と、確認できた場合に正規の UTC RFC 3339 形式の `recorded_at` を返す。\
日時はプロバイダーの記録に属し、操作の開始や終了を推測したものではない。\
`time_state` は `available`、`absent`、`unavailable`、`unsupported` のいずれかで、`available` の場合だけ `recorded_at` を含める。\
日時がない場合や利用できない場合は `event_time_omitted` を追加し、`events` を `partial` にする。

#### 種類ごとのデータ

各イベントは、`kind` に対応するデータを一つ持つ。

##### メッセージ

`message`: `role`（`user` または `assistant`）、記録された `text`、真偽値の `truncated`。

##### ツール呼び出し

`tool_call`: 任意の `call_id` と記録された `name`、必須の `category` と `input_state`、任意の `action` と `input`。

**ツール名**

ツール名はプロバイダー固有の値であり、その意味や構造を共通のツール仕様として定義しない。\
記録された名前がない場合は項目を省略し、`tool_name_unavailable` を報告する。

**操作の分類**

`category` は大まかな分類を示し、`action` がある場合は `execute`、`read`、`search`、`write`、`edit`、`invoke` のいずれかである。

**入力**

`input_state` は [本文の取得状態](#本文の取得状態)、`input` の表現は [内容オブジェクト](#内容オブジェクト) を参照する。

##### ツール結果

`tool_result`: 必須の `outcome`、`correlation_state`、`content_state`、任意の `call_id`、`exit_code`、`content`。

**成否**

`outcome` は `success`、`failure`、`unknown` のいずれかである。\
成功・失敗は、意味を確認したプロバイダーの明示的な項目だけで確定し、`PASS` やエラーらしい文章では判定しない。\
`unknown` でも読める本文を保持し、`tool_outcome_unknown` を追加する。

**内容**

`content_state` は [本文の取得状態](#本文の取得状態)、`content` の表現は [内容オブジェクト](#内容オブジェクト) を参照する。

##### プロバイダーエラー

`error`: `category` と、記録されたプロバイダーエラーの `message`。

#### 呼び出しと結果の対応関係

**対応状態**

`correlation_state` は、次の値を使う。

| 状態 | 条件 | 返す結果 |
| --- | --- | --- |
| `matched` | 選択した論理履歴内の明示的な相関識別子で、呼び出しと結果を一対一に確定できる。 | `call_id` を含む。 |
| `unmatched` | 対応する呼び出しを確定できない。 | 本文を保持し、`call_id` を省略し、`correlation_omitted` を追加する。 |
| `ambiguous` | 呼び出しまたは結果の識別子が重複し、一意に対応できない。 | 本文を保持し、`call_id` を省略し、`correlation_omitted` を追加する。 |

結果に `call_id` を含めるのは、`matched` の場合だけである。\
結果が呼び出しより先に記録されていたり、別のページに現れたりしてもよい。\
識別子がない、または重複した呼び出しは `call_id` なしで保持し、結果の記録がない呼び出しも省略理由を報告する。\
隣接する順序や同じ文章から関係を推測しない。

**対応関係を確定する範囲**

対応付けはページ分割の前に、選択した履歴全体で行う。\
正規化した呼び出し ID は応答の出力形式とは独立した、アダプターが所有する `v0` のアルゴリズム名前空間を維持し、生のプロバイダー相関識別子を公開する呼び出し ID にはしない。

### 内容オブジェクト

`input` と `content` は共通の表現を使う。

```json
{"format":"json","text":"[\"go\",\"test\",\"./...\"]","truncated":false}
```

**フィールド**

内容オブジェクトのフィールドを次に示す。

| フィールド | 規則 |
| --- | --- |
| `format` | `text` または `json`。 |
| `text` | 常に文字列。 |
| `truncated` | 必須の真偽値。 |
| `omitted` | 任意の真偽値。読める内容を残しながら、非テキスト部分や未対応の部分を除外したことを示す。 |

**JSON の保持**

JSON 本文は `truncated` が真でなければ有効な JSON であり、切り詰めた先頭部分は解析できないことがある。\
JSON の整形やオブジェクトの項目順について元のバイト列の保持は保証しないが、制限内で文字列の値と配列の順序を保持する。\
引数の配列は JSON 文字列内の配列として保持し、実行可能なコマンドへ連結しない。

JSON として記録された入力や結果の項目名はプロバイダー固有の値であり、その意味や構造を共通のツール仕様として定義しない。

### 本文の取得状態

`input_state` と `content_state` は、次の値を使う。

| 状態 | 意味と本文の扱い |
| --- | --- |
| `available` | 対応する内容オブジェクトが必須である。空文字列、空のオブジェクト、空の配列も含む。 |
| `absent` | 確認済みの形式で不在と分かる。内容オブジェクトは省略する。 |
| `unavailable` | 期待する情報が欠けている、または読み取れない。内容オブジェクトは省略する。 |
| `unsupported` | 内容の形式に対応していない。内容オブジェクトは省略する。 |

`unavailable` と `unsupported` では、`tool_input_unavailable` または `tool_content_unavailable` の省略理由を追加する。

本文の上限と切り詰めは [個別の本文](#個別の本文) を参照する。

### 検証済みバージョン

出所の証拠や、同じソースの観測結果の比較に、この内容バージョンを使う。\
検証しても、ソースをレビュー済みにはせず、対話記録も保存しない。

#### フィールド

`verified_version` には `algorithm`、`basis`、`value` が必要である。\
現在の値はそれぞれ `sha256`、`provider-content-v0`、`sha256:` を先頭に付けたダイジェストである。

#### 検証済みバージョンの符号化

検証済みバージョンは、ドメイン区切り文字と名前順に並べた証拠チャンクから計算する SHA-256 である。\
各チャンクの名前と内容には、符号なし 64 ビット・ビッグエンディアンのバイト長を前置し、重複するチャンク名は拒否する。

ハッシュには、`schema_version` から独立した専用の `v0` ドメイン分離子と `provider-content-v0` という基準を使う。\
ハッシュ化の意味またはアルゴリズムが変わる場合にだけ、これらを変更する。

### メタデータ

**エントリーの形式**

各メタデータエントリには、トークン値の `name` と安全な文字列 `value` が必要である。\
メタデータ名によって、プロバイダー固有の値にプロバイダーに依存しない意味を与えてはならない。

**プロバイダー固有情報を公開する条件**

プロバイダー固有の成果物の配置、行の種類、相関値は、所有するアダプターの内部に残す。\
安全に公開でき、プロバイダーに依存しない意味を作り出さずに済むサイズ制限内のメタデータを、共通の `metadata` 配列に含めてもよい。

アダプターは、忠実に表現できない重要な値を省略として報告する。\
不安定なプロバイダーフィールドを安定したスキーマへ昇格させたり、同等の共通の意味を推測して `complete` としたりしない。

## 実行結果の判定

### 完全性

#### status

応答の `status` は、次のいずれかの状態を表す。

| 状態 | 意味 |
| --- | --- |
| `complete` | 重要な値が省略、切り詰め、未対応、不明のいずれにもなっていない。 |
| `partial` | 有用な出力はあるが、少なくとも一つの省略を報告している。 |
| `unsupported` | プロバイダーまたは操作が仕様を安全に満たせない。 |
| `error` | 操作が失敗し、構造化エラーを含む。 |

`complete` の応答には、省略もエラーも含められない。\
`partial` の応答には少なくとも一つの省略が含まれる。\
未知のプロバイダー形式や、意味を確定できない値は `complete` にしてはならない。

**ページ分割中の状態**

`has_more: true` のページ分割は、`partial`、コード `pagination` の省略、バージョン付きの `next_cursor` を返す。

#### omissions

各省略は任意のトークン `reason` を含めることができる。\
各省略には、トークン値の `code` と `scope`、安全な人間向けの `message` が必要である。\
任意の正の整数 `count` は、その省略が表す既知の項目数を示す。\
これがないことは、影響を受けるプロバイダー値が 0 件であることを意味しない。

#### 複数プロバイダーの結果の集約

`list` では、複数のアダプターの結果をアダプターの順序とは独立して集約する。\
観測したすべてのアダプター結果が `unsupported` の場合は `unsupported` とし、`unsupported` の省略に `complete` または `partial` の観測を組み合わせた場合は `partial` とする。

### エラー

#### error オブジェクト

構造化エラーには、トークン値の `code` と `category`、固定の人間向けの `message`、Boolean の `retryable`、`details` 配列が必要である。\
各詳細エントリには、トークン値の `name` と安全な文字列 `value` が必要で、配列は空でもよい。\
現在の CLI エラーは再試行可能ではない。

#### エラーカテゴリ

安定したエラーカテゴリは `usage`、`configuration`、`provider`、`resource`、`internal` である。

#### エラーコード

現在のエラーコードは次のとおりである。

- `missing_command`。
- `unknown_command`。
- `invalid_arguments`。
- `invalid_pagination`。
- `invalid_cursor`。
- `invalid_source_ref`。
- `invalid_repository`。
- `source_resolution_failed`。
- `config_path_unavailable`。
- `invalid_configuration`。
- `source_not_found`。
- `provider_failure`。
- `invalid_provider_result`。
- `invalid_archive`。
- `invalid_json`。
- `duplicate_archive_member`。
- `unsafe_archive_member`。
- `source_changed`。
- `provider_resource_limit`。
- `event_limit_exceeded`。
- `verification_failed`。
- `output_bound_exceeded`。
- `response_limit_exceeded`。
- `invalid_result`。

省略とエラーのコード集合は `v2` の中で増やせる。\
`schema_version` を受け入れた後、未知のコードに遭遇した呼び出し側は、結果を `complete` と扱わず、宣言された未完了またはエラー状態を保持しなければならない。

### 終了コード

CLI は次の終了コードを返す。

| 終了コード | 意味 |
| --- | --- |
| `0` | `complete` または `partial` の結果。 |
| `2` | 無効なコマンド、フラグ、カーソル、ソース参照、設定。 |
| `3` | 未対応のプロバイダーまたは操作。 |
| `4` | プロバイダー、I/O、検証、リソース、エンコーディング、内部の失敗。 |

## リソース制限

### 上限一覧

共通の上限を次に示す。

| リソース | 制限 |
| --- | ---: |
| 設定ファイル | 1 MiB |
| バッファリングするプロバイダーまたは検証証拠 | 64 MiB |
| JSON の入れ子 | 64 階層 |
| ソース観測あたりのイベント | 100,000 |
| 動的出力文字列 | 64 KiB |
| 一つの発言・ツール入力・ツール結果の内容 | 64 KiB |
| ソースまたはイベントあたりのメタデータエントリ | 64 |
| ソースあたりの関係 | 64 |
| ページサイズ | 既定 50、最大 100 |
| エンコード済み応答 | 8 MiB |

### 入力上限の適用範囲

共通の 64 MiB の証拠制限は、証拠チャンクを CLI に返すアダプターに適用する。\
アーカイブアダプターは、プロバイダーが定める制限内のより大きなソースを、証拠チャンクとして実体化せずに同じ `provider-content-v0` 検証済みバージョンアルゴリズムへストリーム処理してよい。\
プロバイダー固有の入力制限は各アダプターに記載し、8 MiB の応答制限を増やすものではない。

### 出力上限を超えた場合の扱い

#### 文字列フィールド

切り詰めた動的出力には `resource_truncation` の省略を追加し、完全な状態のままにはできない。

自由形式の文字列は、有効な UTF-8 の境界でのみ切り詰める。\
サイズ超過した生のプロバイダー固有ソース ID は省略するが、フィンガープリントとソース参照は保持する。\
サイズ超過した構造上の識別子は、別の識別子へ切り詰めず、構造化されたリソースエラーとして安全側に失敗する。

#### 個別の本文

一つの内容全体を 64 KiB に制限し、複数の結果欄や文章ブロックがあっても上限を増やさない。\
内容を切り詰めた場合は `truncated` と `tool_input_truncated` または `tool_content_truncated` を報告し、応答全体も `partial` にする。\
共通の最終出力処理による切り詰めは `resource_truncation` を報告する。\
非テキスト部分や未対応の部分を除外した場合は `unsupported_content` などの省略理由を報告する。\
一つの本文の続きを取得する機能はない。

一つの本文自体の切り詰めは、ページの件数を減らしても回復しない。

#### 応答全体

JSON エンコード後に応答が 8 MiB を超える場合は `response_limit_exceeded` を返し、部分的な JSON を出力しない。\
ページ分割する操作では、同じ取得位置で `--limit` を減らして再試行できる。\
同じ要求をそのまま再試行しても解決しないため、`retryable` は偽のままである。\
一つの本文自体の切り詰めは、件数を減らしても回復しない。

## 記録内容の取り扱い

### 本文の公開方針

記録された内容は自動で隠さずに返し、認証情報らしい値、パス、ホスト名、コード、検索文字列、コマンドの文章を含むことがある。\
内容を隠す切替設定はなく、`redaction_policy_version` は出力しない。\
呼び出し側が分析、保存、外部への共有に使う内容を決める。

### 信頼できないデータの扱い

記録された内容は、信頼できないデータとして扱う。\
実行したり、現在の指示として扱ったりしない。

### 診断に含める情報

CLI の診断には、基になったエラーや元の記録を不必要にコピーしない。

基盤となるエラー、ソースルート、生の引数は、公開診断へコピーしない。

## 呼び出し側の処理手順

### 全ページを取得する

`list` と `events` では、明示したルートや設定も含め、各要求で同じソースを選ぶ。

次の手順でページを取得する。

1. バージョン依存のフィールドを解釈する前に、`schema_version` を検証する。
2. `status` と `omissions` を調べ、利用可能な操作データを読む。
3. `page.has_more` が `true` なら、`page.next_cursor` を変更せず、同じ操作に渡す。
4. `has_more` が `false` になるまで取得し、全ページの省略を保持する。

返されたカーソルは、次の形で指定する。

```sh
agent-sessions list --provider codex --limit 50 --cursor '<page.next_cursor>'
agent-sessions events --limit 50 --cursor '<page.next_cursor>' '<source_ref>'
```

**最終ページ取得後の完全性**

全ページを取得しても、ほかの省略は解消せず、終了コード `0` も完全性の証明にはならない。\
ページの件数を減らしても、個別に切り詰めた本文は回復しない。\
詳細は [個別の本文](#個別の本文) を参照する。

**要求の間にソースが変わる場合**

元の記録が取得の間に変わると、位置に基づくページ分割では一定の記録の完全取得を保証できない。\
同じ元データと実行ファイルで取得し、必要に応じて前後の検証済みバージョンを比較する。

### 最近のソースを選ぶ

一定期間内のソースは、次の手順で選ぶ。

1. `list` の全ページを取得する。
2. `last_interaction_at` がないソースを、時刻が分かる対象から除外する。
3. 対象期間の判定では、時刻を絶対日時として比較する。
4. 対象を `last_interaction_at` の降順、同じ時刻なら `identity.source_ref` の昇順で並べる。

ソースの時刻が欠けている場合や未取得のページがある場合など、`partial` の一覧からは対象の全件を確定できない。

### v1 対応の呼び出し側を更新する

変更されたフィールドと内容の扱いは [v1 からの変更点](#v1-からの変更点) を参照する。

固定した実行ファイルを更新する前に、次の内容を確認する。

1. 呼び出し側で v2 を受け入れ、入力と結果の内容を読めるようにする。
2. 不明な値と省略を扱えるようにする。
3. 保存と共有の範囲を確認する。

**以前の実行ファイル**

v1 が必要な場合や連携処理に問題が出た場合は、以前の実行ファイルを保持するか、以前のものに戻す。

## バージョン管理

### 応答スキーマの変更規則

追加の任意フィールドは `v2` の中で導入できる。\
必須フィールドの削除や変更、既存フィールドの意味の変更、状態、イベント種別、終了コード、論理識別子の規則、その他の必須意味の非互換な変更には、新しいメジャースキーマバージョンが必要である。

### 各形式の独立したバージョン管理

`cli_version` は実行ファイルのバージョンを示し、応答スキーマを選択するものではない。\
設定スキーマは別に検証され、現在は `v1` だけを受け付ける。

ソース参照、フィンガープリントのハッシュ化、検証用のハッシュ化、呼び出し ID、カーソルも、応答スキーマとは独立した版を持つ。\
形式は [論理識別子](#論理識別子)、[検証済みバージョンの符号化](#検証済みバージョンの符号化)、[呼び出しと結果の対応関係](#呼び出しと結果の対応関係)、[ページ情報](#ページ情報) で定義する。

### v1 からの変更点

**変更された動作**

v2 は内容を自動で伏せる保証を削除し、入力、結果、成否不明、対応先不明を表す。\
`success`、`excerpt`、`redacted`、`evidence_state` は新しい項目へ置き換え、`input_state: withheld` は `available` と実際の `input` に置き換える。\
新しい実行ファイルに v1 の出力を選ぶ機能はない。

**変更されない形式**

設定ファイルの `schema_version: v1`、コマンドと引数、ソース参照、検証用ハッシュの方式は変わらない。
